# Практическая работа №2 — Гипотезы роста выручки

**Курс:** Управление информационными технологиями на предприятии  
**Семестр:** осень/зима 2026  
**Объект исследования:** ATI.SU  
**Финансовый контур:** ООО ИА «АВТОТРАНСИНФО», ИНН 7810518403  
**База расчёта:** выручка 2025 года — **1 475 795 000 ₽**  
**1% выручки:** **≈ 14,8 млн ₽**

---

## Краткая версия паспорта проекта

1. **Бизнес:** ATI.SU — SaaS / цифровая B2B-платформа для транспортной логистики.
2. **Масштаб:** выручка ООО ИА «АВТОТРАНСИНФО» — **1 475 795 000 ₽ за 2025 год**.
3. **Направления:** лицензии и платные функции ATI.SU, «Площадки ATI.SU», API и аналитика; после эпизода 1 дополнительно рассматривается коммерческий продукт на данных.
4. **ИТ-функция:** крупная собственная продуктовая разработка; после эпизода 1 диагноз **«Партнёр» сохраняется, зона состояния ИТ снижена с 🟢 до 🟡**.
5. **Ограничения:** используются открытые данные и условия игровых сценариев; неизвестные внутренние показатели не подменяются выдуманными baseline.

# 1. Исходная точка из ПР1

ПР2 строится на обновлённой ПР1 после одновременных лебедей №37 и №55.

После эпизода 1 зоны ПР1 выглядят так:

| Блок | Зона |
|---|:---:|
| Направления / монетизация | 🔴 |
| Клиенты и каналы | 🔴 |
| Ключевые процессы | 🔴 |
| ИТ-функция | 🟡 |
| Связь и безопасность | 🔴 |
| Состояние ИТ | 🟡 |

Ключевые проблемы, из которых должны вырасти гипотезы:

- после массовой миграции часть клиентов потеряла рейтинги, отзывы и историю;
- появились дубли компаний и fraud-кейсы;
- часть грузовладельцев ушла к третьему игроку;
- банки требуют объяснить, почему обещанная синергия превратилась в падение выручки;
- ключевые сотрудники приобретённой компании получают предложения рынка;
- есть области с потенциальным `bus factor = 1`;
- данные приобретённой платформы нельзя автоматически использовать в новом data-продукте;
- новый аналитический продукт должен пройти consent/contract mapping, Legal + Security gate и проверку риска повторной идентификации;
- сценарии №37 и №55 конкурируют за одни product/data/security/architecture-ресурсы.

# 2. Отраслевой коридор

Коридор курса для ATI.SU:

| Показатель | Коридор |
|---|---:|
| Одно улучшение на выручку | **0,5–2% годовой выручки** |
| Одно улучшение на затраты | **2–10% конкретной статьи затрат** |
| Набор из пяти улучшений | **1,5–5% годовой выручки** |

Для базы **1 475 795 000 ₽**:

- **0,5% ≈ 7.4 млн ₽**;
- **1% ≈ 14.8 млн ₽**;
- **2% ≈ 29.5 млн ₽**;
- нижняя граница набора 1,5% ≈ **22.1 млн ₽**;
- верхняя граница набора 5% ≈ **73.8 млн ₽**.

Эффекты гипотез ниже являются **оценками для проверки**, а не уже полученным результатом.

Для гипотез на затраты процент считается от конкретной статьи расходов. Если размер статьи неизвестен, рублёвый эффект до базового замера не рассчитывается.

# 4. Гипотеза №1 — безопасная волновая миграция клиентов

**Тип:** гипотеза про ИТизацию.

| Поле | Содержание |
|---|---|
| **Формулировка** | **Если автоматизировать сверку профилей, рейтингов и истории и переводить клиентов малыми волнами через quality gates с возможностью rollback, то миграционный churn снизится и компания сохранит дополнительно 0,8–1,2% годовой выручки, потому что ошибки идентичности и неполного переноса будут выявляться до массового воздействия на клиентов.** |
| **Строка P&L** | Выручка — сохранённая выручка от платных клиентов и лицензий |
| **Показатель и текущее значение** | Потеря платной выручки / churn, связанный с миграцией. **Текущее значение неизвестно — требуется базовый замер по billing и клиентским когортам.** |
| **Порог** | В пилотной волне annualized retained revenue effect не ниже **0,8% базы** (≈ **11.8 млн ₽**) и не возникает повторения уже выявленного механизма массовой потери рейтингов/истории |
| **Срок проверки** | 2 месяца после запуска первой контролируемой волны |
| **Опровергающее наблюдение** | Ошибок переноса становится меньше, но churn и потеря платной выручки у мигрированной когорты не улучшаются относительно сопоставимой когорты — значит, основная причина ухода клиентов не в механике миграции |
| **Риск или неопределённость** | Неопределённость: часть клиентов могла потерять доверие необратимо; технически корректная миграция не гарантирует возврат |
| **Что нужно для проверки** | Billing по клиентам, история лицензий, причины churn, журнал миграционных ошибок, данные по рейтингам/истории, две сопоставимые клиентские когорты, механизм rollback |
| **Допущения** | Эффект **0,8–1,2%** — сценарная оценка внутри отраслевого коридора; исходный migration-attributable churn пока не измерен |

**Источник из ПР1:** блоки 1.3 «Клиенты и каналы», 1.4 «Ключевые процессы», 1.6 «Связь и безопасность», долг №37 по восстановлению клиентов.

# 6. Гипотеза №3 — программа удержания пострадавших клиентов

| Поле | Содержание |
|---|---|
| **Формулировка** | **Если пострадавшим платным клиентам дать ограниченный recovery-пакет — сохранение тарифа на переходный период, приоритетную поддержку и дополнительный доступ к полезной функции, — то отток в этой группе снизится и будет сохранено 0,5–0,8% годовой выручки, потому что клиент получит реальную компенсационную ценность в период восстановления доверия.** |
| **Строка P&L** | Выручка — сохранённые лицензии / повторные оплаты |
| **Показатель и текущее значение** | Churn платных клиентов, затронутых миграцией. **Текущее значение неизвестно — требуется сегментация причин ухода и замер когорты.** |
| **Порог** | Churn recovery-группы минимум на **20% ниже**, чем у сопоставимой группы без пакета, а annualized retained revenue effect — не ниже **0,5% базы** (≈ **7.4 млн ₽**) |
| **Срок проверки** | 2 месяца |
| **Опровергающее наблюдение** | Клиенты используют компенсацию, но churn не отличается от сопоставимой группы либо стоимость компенсации съедает ожидаемый финансовый эффект |
| **Риск или неопределённость** | Риск каннибализации: компенсацию могут получить клиенты, которые и так не собирались уходить; неизвестна реакция разных сегментов |
| **Что нужно для проверки** | Сегментация пострадавших клиентов, billing, причины churn, стоимость компенсационного пакета, контрольная/сопоставимая группа |
| **Допущения** | Оценка эффекта **0,5–0,8%** находится внутри коридора; предполагается, что пакет имеет низкую предельную стоимость по сравнению с сохраняемой выручкой |

**Источник из ПР1:** красная зона «Клиенты и каналы», долг по оттоку и предложенная компенсационная реакция после №37.

# 10. Формула приоритизации

Чтобы сопоставить гипотезы на выручку и на затраты, используется нормированная формула:

> **Priority = 40 × E + 25 × C + 20 × U + 15 × T**

где все множители находятся в диапазоне от 0 до 1.

### E — нормированный экономический эффект

Для гипотезы на выручку:

> `E = середина диапазона эффекта / 2%`

Для гипотезы на затраты:

> `E = середина диапазона эффекта / 10%`

2% и 10% — верхние границы отраслевого коридора одного улучшения.

### C — доказательность

| Значение | Правило |
|---:|---|
| 1,00 | есть фактический baseline и подтверждённая причинная связь |
| 0,75 | проблема подтверждена сценарием/ПР1, но baseline эффекта ещё не измерен |
| 0,50 | спрос/механизм задан сценарием, но ключевые ограничения и baseline неизвестны |
| 0,25 | гипотеза в основном держится на допущениях |

### U — срочность

| Значение | Правило |
|---:|---|
| 1,00 | уже идёт потеря денег/доверия или есть долг к ПР2 |
| 0,75 | обязательство в горизонте до 12 месяцев |
| 0,50 | результат нужен в горизонте 18 месяцев |
| 0,25 | нет жёсткого срока |

### T — скорость проверки

| Значение | Правило |
|---:|---|
| 1,00 | ≤ 2 месяцев |
| 0,75 | ≤ 3 месяцев |
| 0,50 | ≤ 6 месяцев |
| 0,25 | > 6 месяцев |

Шкалы **C, U и T являются правилами этой работы**, а не внешними отраслевыми нормативами. Они применяются одинаково ко всем гипотезам.

### Проверка E

- №1: середина 0,8–1,2% = **1,0%**; `1,0 / 2,0 = 0,50`.
- №2: середина 4–6% = **5% статьи**; `5 / 10 = 0,50`.
- №3: середина 0,5–0,8% = **0,65%**; `0,65 / 2 = 0,325`.
- №4: середина 0,5–1,0% = **0,75%**; `0,75 / 2 = 0,375`.
- №5: середина 5–8% = **6,5% статьи**; `6,5 / 10 = 0,65`.

---

# 12. Что берётся в ПР3

## Берём в работу

### №1. Безопасная волновая миграция — Priority 73,75

Причина: непосредственно закрывает красные зоны клиентов, процессов и безопасности; является обязательной гипотезой про ИТизацию и может быть проверена быстро.

### №3. Recovery-пакет для пострадавших клиентов — Priority 66,75

Причина: работает напрямую с уже возникшим оттоком и позволяет быстро проверить, какая часть churn ещё обратима.

### №2. Удержание критических сотрудников и knowledge transfer — Priority 66,25

Причина: без этой гипотезы следующая миграция и последующее отключение дублирующих систем остаются зависимыми от отдельных носителей знания.

Именно процессы, обслуживающие эти три гипотезы, должны перейти в ПР3.

---

# 13. Что оставляется в резерве

### №5. Сокращение дублирующих ИТ-затрат — Priority 52,25

**Не отвергается**, но зависит от №1 и №2. Нельзя ускорять отключение систем ради синергии до восстановления клиентов и передачи знаний — именно такая гонка уже привела к плохому исходу №37.

Переводится в активную работу после:

- стабильных миграционных волн;
- классификации application portfolio;
- отсутствия критических `bus factor = 1`;
- базового замера run-cost.

### №4. Коммерческий data-продукт — Priority 46,25

Также **не отвергается**. Но сейчас у него самый высокий уровень неопределённости:

- неизвестен фактически допустимый периметр данных;
- данные приобретённой компании нельзя использовать автоматически;
- часть крупных клиентов возражает;
- требуется закрыть incident/data-governance долги;
- продукт конкурирует за product/data/security-ресурсы с recovery №37.

До перехода в активную работу должны быть выполнены consent/contract mapping и первичный коммерческий тест на допустимом наборе данных.

# 15. Какие данные нужно снять до следующего шага

До ПР3 желательно получить или смоделировать из учебного контекста следующие baseline:

1. текущий GRR/churn после эпизода;
2. потерю платной выручки по причинам миграции;
3. размер и стоимость recovery-пакета;
4. число конфликтных профилей и неполных переносов;
5. число критических областей с `bus factor = 1`;
6. стоимость rework и внешней поддержки интеграции;
7. application portfolio и run-cost дублирующих систем;
8. допустимый периметр данных для №55;
9. первые данные по willingness-to-pay data-продукта.

Если преподаватель не предоставляет этих значений, они остаются в отчёте как **неизвестные baseline**, а не заменяются случайными числами.

# 16. Итог

Из обновлённой ПР1 сформированы пять проверяемых гипотез.

Главный приоритет — **не ускорять синергию любой ценой**, а сначала остановить утечку клиентской ценности и сохранить знания, необходимые для безопасного объединения.

В ПР3 переходят:

1. **безопасная волновая миграция клиентов** — ИТизация;
2. **recovery-пакет для пострадавших платных клиентов**;
3. **удержание критических сотрудников и передача знаний**.

В резерве остаются:

4. **коммерческий data-продукт** — до подтверждения допустимого периметра данных и спроса;
5. **отключение дублирующих систем** — до стабилизации клиентов и knowledge transfer.

Такой порядок не отменяет бизнес-цели двух лебедей, но меняет последовательность: сначала восстановление выручки и управляемость интеграции, затем масштабирование нового data-направления и получение полной синергии.
