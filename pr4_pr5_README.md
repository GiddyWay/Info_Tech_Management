## Воспроизведение расчёта

В каталоге файлов запустить `python pr4_model.py`, затем `python pr4_model.py --check`. Нужен Python 3.10 или новее, дополнительных пакетов нет. Все входы находятся в начале скрипта, unit conventions и источники раскрыты в ПР4. Код перезаписывает только файлы результатов:

- `pr4_model_results.json` — точные суммы и формулы сценариев;
- `pr4_scenario_results.csv` — три сценария;
- `pr4_synthetic_periods.csv` — два **синтетических** периода для демонстрации calibration/holdout;
- `pr4_synthetic_distributions.csv` — распределения двух метрик, **синтетика**.

Датированный [прогноз](./pr4_forecast_2026-11-19.md) не перезаписывается моделью. Хеш в `pr4_forecast_2026-11-19.sha256` проверяет сохранность содержания, но не удостоверяет время независимо. Для подтверждения записи до начала периода требуется коммит/передача преподавателю; отправка или публикация от имени студента не выполнялась.

`pr5_build_presentation.mjs` — исходник презентации для bundled `@oai/artifact-tool`. Требует переменные `CODEX_PRIMARY_RUNTIME_NODE_MODULES`, `CODEX_PRIMARY_RUNTIME_PYTHON`, `PRESENTATIONS_SKILL_DIR`; затем `node pr5_build_presentation.mjs`. Скрипт читает JSON модели и сохраняет итоговый PPTX; проверка таблицы пересечений и структуры встроена. Текстовые отчёты при изменении входов обновляются отдельно.

## Важное ограничение сдачи

Внутренняя история ATI.SU не предоставлена. Поэтому **реальная историческая валидация ПР4 не выполнена**; синтетические периоды не названы выгрузкой компании. План получения реальных данных и правила допуска модели описаны в ПР4. Нельзя заменять пометку synthetic на measured или заявлять подтверждённую точность/эффект без реальных данных.

Паспорт, ПР1 и ПР2 сохранены без изменений. Из предыдущих работ исправлены только ПР3 и её план замеров. №37 и №55 остаются предысторией, новые действующие назначения — №3 и №5.
